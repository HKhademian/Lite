# Lite Proposal register

Status: **design record, 2026-10-27; no release is created by this register**.

Proposals follow [the selected versioning policy](lite://doc/versioning-and-naming#8-proposal-versioning). Each record has a stable LP ID, revision, status, target version or unassigned marker, and supersession information. Accepted proposal text is retained; a later contract change requires a new revision or proposal rather than a silent edit.

## Accepted and unreleased

- [LP-0001 r1: Operation-specific panic recovery](lite://doc/proposals/LP-0001-operation-specific-panic-recovery). Target language and compiler/runtime versions: unassigned. An operation handler covers its defined faults; argument/operand panics bypass it.
- [LP-0002 r1: Explicit whole-block panic recovery](lite://doc/proposals/LP-0002-explicit-block-panic-recovery). Target language and compiler/runtime versions: unassigned. An explicit block covers supported typed panics from its executed contents and synchronous calls.
- [LP-0003 r1: Pending-failure munching](lite://doc/proposals/LP-0003-pending-failure-munching). Target language and compiler/runtime versions: unassigned. Clauses consume their matches in written declaration order; singleton, aggregate, and empty remainders share one recovery model.

- [LP-0004 r1: Count-free error contracts](lite://doc/proposals/LP-0004-count-free-error-contracts). Target language and compiler/runtime versions: unassigned. Error declarations admit types without occurrence counts; complete recovery cannot require predicting multiplicity. LP-0009 subsequently extends the singular Result description to stored occurrences while retaining this count-free rule.

- [LP-0006 r1: Whole-match failure consumption](lite://doc/proposals/LP-0006-whole-match-failure-consumption). Target language and compiler/runtime versions: unassigned. Ordinary catches consume all their matches; the later LP-0007 selects explicit ellipsis collection, including singleton capture.

- [LP-0007 r1: Typed recovery collectors and occurrence order](lite://doc/proposals/LP-0007-typed-recovery-collectors). Target language and compiler/runtime versions: unassigned. Selects ...errs: Error with errs typed [Error], singleton capture, once-per-clause execution, and stable filtered occurrence order. LP-0009 subsequently selects Failure for both channels and extends the stored failure side to multiple occurrences; this accepted r1 text is retained as history.

- [LP-0008 r1: Recovery block tags and temporary traces](lite://doc/proposals/LP-0008-recovery-block-tags-and-traces). Target language and compiler/runtime versions: unassigned. Protected-block tags exclude attached handlers; explicit wrapper blocks and handler-local tags define return scope. Temporary traces are a review technique, not retroactive panic boundaries.

- [LP-0009 r1: Explicit capture and flat failure outcomes](lite://doc/proposals/LP-0009-flat-failure-capture). Target language and compiler/runtime versions: unassigned. Selects whole-operand postfix ? capture, flat T ! (E | Panic), one-outward-layer normalization, stored ordered occurrences, and Error/Panic/Failure selectors. Extends earlier singular Result descriptions without changing count-free error declarations.
- [LP-0010 r1: Outcome extraction and failure exhaustion](lite://doc/proposals/LP-0010-outcome-extraction-and-exhaustion). Target language and compiler/runtime versions: unassigned. ! extracts one success layer or forwards retained failures with original channels; complete static recovery yields an ordinary value without another !.

- [LP-0012 r1: Manual failures and escaping-error inference](lite://doc/proposals/LP-0012-manual-failures-and-error-inference). Target language and compiler/runtime versions: unassigned. Selects custom failure capability, category-based raise expression, and eligible omitted-output inference of escaping returned errors. Explicit/expected contracts remain constraints; implicit panics are excluded from inferred E. LP-0014 subsequently supersedes the bare-Panic local-interception direction; accepted r1 text is retained.

- [LP-0013 r1: Scalar recovery selection and discarded matches](lite://doc/proposals/LP-0013-scalar-recovery-selection). Target language and compiler/runtime versions: unassigned. Typed scalar receivers expose the first matching occurrence and consume/discard other matches, leaving different categories untouched; ellipsis exposes every match.
- [LP-0014 r1: Directed failure exits and explicit block targets](lite://doc/proposals/LP-0014-directed-failure-exits). Target language and compiler/runtime versions: unassigned. Scalar/group raise defaults to the nearest function/closure for both Error and Panic; an explicit tag selects an enclosing block. Transfer skips inner recovery, with surrounding target recovery still eligible. Supersedes LP-0012's bare-Panic local interception. LP-0015 later resolves normal function-return abandonment; other unmatched-remainder exit policies remain open.

- [LP-0015 r1: Early function returns and continuing recovery paths](lite://doc/proposals/LP-0015-early-return-recovery-paths). Target language and compiler/runtime versions: unassigned. Plain return abandons unfinished captured recovery and returns its success value; other captured failures are not implicitly forwarded or grounds for an extra handling rejection. Residual types describe continuing paths only. Other exit kinds retain their separate policy.

- [LP-0016 r1: Recapture and suppressible warnings](lite://doc/proposals/LP-0016-recapture-and-warning-policy). Target language and compiler/runtime/tooling versions: unassigned. Recapture preserves one outward outcome layer and all occurrences; type equality alone does not imply redundancy. Optional proof-based warnings and all warnings generally are suppressible; control syntax remains open.
- [LP-0017 r1: Result failure occurrence patterns](lite://doc/proposals/LP-0017-result-failure-occurrence-patterns). Target language and compiler/runtime versions: unassigned. .err(e) exposes the first occurrence; .err(...es) exposes all in order, without mutating the source, searching scalar subpatterns, or flattening occurrence internals.
- [LP-0018 r1: Implicit panics without effect declarations](lite://doc/proposals/LP-0018-implicit-panics-without-effect-declarations). Target language and compiler/runtime versions: unassigned. Prohibits checked live-panic effect lists, retains literal first-class captured outcomes and broad live-panic capture, and leaves non-exhaustive documentary fault annotations for investigation.

These are the first actual proposal records in this repository; LP numbers used as illustrative examples in the naming/versioning page do not reserve proposal IDs. Historical ledger entries are not retroactively renumbered.

## Drafts under review

Retains the expensive-fallback and earlier bracket-capture proposal history, follows the selected LP-0007 collector, and reviews residual untyped binding, optional domain-owned count/details, retention/transport, and failure-directed/tagged exits with unhandled remainders. LP-0015 now resolves plain early function return as abandonment of unfinished captured recovery. LP-0013 resolves typed scalar binding; LP-0014 resolves raise targets/groups.

- [LP-0011 r4: Explicit failure raising from recovery](lite://doc/proposals/LP-0011-explicit-failure-raising). Target language and compiler/runtime versions: unassigned. Follows accepted LP-0013 scalar selection/discard and LP-0014 directed scalar/group raises and block targets. LP-0015 now resolves plain-return abandonment. The remaining draft is failure-directed/tagged-exit remainder policy and provenance/transport; syntax and destinations are selected.

## Current reference and release boundary

The [decision ledger](lite://doc/decisions-and-open-questions), [expression recovery](lite://doc/expression-recovery), [grammar sketch](lite://doc/grammar-sketch), [capture and unwrapping](lite://doc/failure-capture-and-unwrapping), [manual failures and inference](lite://doc/manual-failures-and-inference), and [LS-008 summary](lite://spec#ls-008--errors-recovery-and-cleanup) describe current selected contracts and remaining gaps. Detailed normative pages own the current rules; proposal records preserve the accepted decisions. [Recovery-boundary traces](lite://doc/recovery-boundaries) are supporting analysis, while unbraced broad operation-else recovery remains historical. The separately explicit ? boundary now selects broad operand capture.

Acceptance alone does not bump the language, compiler, runtime, CLI, or ABI version. Target versions and the release manifest are assigned when changes ship. No release tag, compatibility claim, compiler implementation, or conformance result is created here. Whole-match consumption, typed ellipsis collectors, and once-per-clause execution are selected. Failure is now the all-failures selector under LP-0009. Untyped broad binding, complete filter parsing, physical carrier construction/origin APIs, storage/retention, operation fault attribution, custom category declaration/conformance, failure-directed/tagged-exit remainder policy, recursive/public inference, and mixed-channel transfer/exit integration remain open. Manual raise and eligible omitted-output escaping-error inference are selected in LP-0012. LP-0013/LP-0014 now select typed scalar first-match/discard and directed scalar/group raise with explicit block targets. LP-0015 now settles ordinary early function return from captured recovery. LP-0016–LP-0018 now settle recapture, Result occurrence inspection, and the prohibition of checked live-panic effects. Documentary fault metadata remains under investigation. See [the focused shortfalls list](lite://doc/failure-handling-shortfalls).
