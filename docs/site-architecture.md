# Static Site Architecture & Portable Curriculum Schema

Status: current site architecture reference, 2026-11-16.

The Lite static site (`dist/site/`) is generated deterministically in build-time TypeScript (`node ./site/build.ts`) without external website dependencies, frontend frameworks, or checked-in build outputs. All UI, syntax highlighting, browser compilation, and grading run locally from static HTML, CSS, and stripped ES modules emitted at build time.

There are no separate school, study, or university academic tracks; all guided learning lives under **Lite Academy**, unifying **Docs** (Handbook & Spec), **References** (`core/*` & `extra/*` Modules and Tools), **Gym**, and **Play**.

See [documentation maintenance](documentation.md) and [the documentation index](README.md) for authoring and link-checking policy.

## Shared Browser Worker Protocol (`runtime/worker.js`)

The Web Worker generated by [playground-worker.ts](../site/playground-worker.ts) is shared across `/playground/`, `/learn/`, and `/gym/`. It loads `compiler.js`, `compiler-c.js`, and `stdlib.json` lazily once per worker instance and executes stripped JS against an in-memory `process` stub (`stdin`, `argv`, `node:fs` read/write descriptors):

- **`action: "compile"`**: Compiles Lite source (using `extraModules` if provided, e.g. tutorial multi-file helper modules) to both TypeScript and C, returning `{ ok, ts, c, cError, stderr }`.
- **`action: "compile-c"`**: Runs only the C backend compiler for on-demand C preview (`{ ok, c, stderr }`).
- **`action: "run"`**: Compiles Lite to TypeScript, strips types via `stripLiteTs`, wires interactive Play hooks via [play-keepalive.ts](../site/play-keepalive.ts), and executes `main()` with `{ stdin, args }`. Static or animated `extra/canvas` frames and `extra/audio` tone queues are returned in `{ frame, canvas, play, tones }`.
- **`step`, `keydown`, `keyup`, `pointermove`, `pointerdown`, `pointerup`, `stop`**: Drive live `extra/canvas` + `extra/audio` Play loops frame-by-frame.
- **`action: "grade"`**: Compiles Lite once and executes `cases: Array<{ name, stdin, args, expectedStdout, hidden }>` sequentially with a fresh Play/process state per case. Replies with `{ ok, action: "grade", allPassed, ts, stderr, results }`. When `hidden: true`, `expectedStdout` and `actualStdout` are omitted from the worker result payload so browsers never leak hidden assertion strings.

## Documentation & API Extraction Pipeline

Markdown and `.lts` module docs are rendered without external JavaScript Markdown dependencies:

- [markdown-html.lts](../lib/util/markdown-html.lts) implements a Pure-Lite CommonMark/GFM-subset renderer (`renderMarkdown`) emitting semantic headings with stable fragment slugs, alerts, tables, fenced code blocks (`data-lang` + `data-fence`), and `data-md-href` placeholders for relative `.md`/`.lts` links.
- [docgen.lts](../lib/util/docgen.lts) parses `pub` declarations and doc comments across `lib/core/*.lts` and `lib/extra/*.lts`, feeding `/modules/` pages and global search symbols.
- [docs.ts](../tools/docs.ts) exposes compiled `renderDocuments(paths, root)` and `extractModules(root)` helpers to the Node site generator, while [docs-pages.ts](../site/docs-pages.ts) applies [status classification](documentation.md#truth-and-freshness) pills (`Verified in TS`, `Selected Design`, `Working Proposal`, `Historical`, `Open Question`), rewrites every `data-md-href` to its published HTML route, and enforces zero broken local `href`s at build time.

## Portable Curriculum & Gym Schemas (MiniLang Reuse Checklist)

To deploy this same learning, gym, docs, and playground portal for a sister language repository (such as MiniLang):

1. **Adopt the JSON catalog contracts**:
   - Mirror [learn.schema.json](../config/learn.schema.json) under `config/learn.schema.json` with domain-hierarchical guides/sources (`<domain>/<subGroup>/<slug>`) and track metadata (`getting-started`, domain tracks, `tutorials`).
   - Mirror [gym.schema.json](../config/gym.schema.json) under `config/gym.schema.json` with `<domain>/<subGroup>/<slug>/{README.md,starter.*,solution.*}`, visible/hidden cases, progressive hints, and `expectedStarterFailure`.
2. **Swap language-specific build adapters**:
   - Emit browser-runnable compiler artifact(s) (`compiler.js` / `stdlib.json`) compatible with `worker.js` or replace `compileWith` / `stripLiteTs` inside the worker adapter.
   - Update tokenizer keywords/operators/types in [highlight.ts](../site/highlight.ts) and code-simplification patterns in [code-view.ts](../site/code-view.ts).
3. **Preserve build-time verification invariants**:
   - Require every lesson program, tutorial, and Gym solution to compile and match expected outputs (and every starter to fail as declared) at site-build time via a corpus verifier akin to [gym-verify.ts](../site/gym-verify.ts).
   - Keep an automated local link/fragment check (`lite docs --check`) and post-build HTML `href` crawler (`docs/`, `learn/`, `gym/`) in the test suite so documentation and portal routes cannot drift.
